# Лаборатория выкатывается в свой проект Vercel из GitHub Actions через CLI, а не Git-интеграцией

Лаборатории нужен отдельный проект Vercel `athletics-gym-lab`: production — из `main`, превью — на каждый PR, функции в `fra1` рядом с базой TiDB Cloud (eu-central-1). В том же репозитории живёт старый проект `athletics-gym`. У него Root Directory `.`, и он отвечает только за редирект `athletics-gym.vercel.app` → athleticsgym.kz (ADR 0004, выкатка из `ops/vercel-redirect`). Его трогать нельзя. Корневой `vercel.json` с `"git": { "deploymentEnabled": false }` читают **оба** проекта: настройка относится к репозиторию, а не к проекту. Поэтому:

- если включить Git-деплои в корневом `vercel.json`, push в `main` может снова собрать сайт в старый проект (если Git у него подключён) поверх редиректа, а это сломает перенос адреса в Search Console;
- если оставить их выключенными, Git-интеграция нового проекта не выкатит ничего.

Решение: корневой `vercel.json` не меняем, Git-деплои остаются выключенными для всех проектов. Лабораторию выкатывает workflow `.github/workflows/lab.yml` командой `vercel deploy` (сборка на Vercel из исходников): push в `main` → `--prod`, PR → превью, адрес превью — в комментарии к PR. Проект задаётся только переменными `VERCEL_ORG_ID` / `VERCEL_PROJECT_ID` (переменные репозитория GitHub `VERCEL_ORG_ID`, `VERCEL_LAB_PROJECT_ID`), а шаг выкатки отказывается работать с ID старого проекта. Токен — секрет репозитория `VERCEL_TOKEN`. Без него workflow выдаёт предупреждение и пропускает выкатку (CI не краснеет). Регион функций — `fra1` из того же `vercel.json`.

## Considered Options

- **Включить Git-деплои и отключить Git у старого проекта** — нарушает правило «старый проект не трогаем».
- **`ignoreCommand` в `vercel.json`, различающий проекты по `VERCEL_PROJECT_ID`** — ошибка в скрипте (код выхода 1) означает «собирать», то есть сбой привёл бы к выкатке `main` в старый проект. Отказ в опасную сторону — неприемлемо.
- **Отдельная Root Directory для Лаборатории** — Next-приложение лежит в корне, сборка из подпапки хрупкая.
- **`vercel build` в Actions + `deploy --prebuilt`** — сборка в Actions требует вытягивать переменные проекта (вместе с секретами) в раннер. Сборка на Vercel проще и держит секреты только в Vercel.

## Consequences

- Превью и production Лаборатории пишут в одну базу TiDB: это синтетические данные, сброс — `npm run seed:lab`.
- **Привязка папок к проектам (с 17 октября 2026):** корень репозитория — `athletics-gym-lab`, `ops/vercel-redirect` — `athletics-gym`. Случайный `vercel deploy` из корня попадает в Лабораторию, а не в редирект прода. Сделать сайт сборкой старого проекта можно только из `ops/vercel-redirect`, где лежит лишь редирект. `.vercel` не в git, поэтому на новой машине привязку делают так: в корне `vercel link --yes --project athletics-gym-lab`, в `ops/vercel-redirect` — `vercel link --yes --project athletics-gym`. `vercel link` выкачивает переменные проекта в `.env.local`: после привязки этот файл лучше удалить. До 17 октября корень был привязан к старому проекту, и `vercel deploy --prod` из корня заменил бы редирект сайтом.
- Ручная выкатка Лаборатории с машины разработчика — `vercel deploy --prod` из корня. Секреты и черновики при этом отсекает `.vercelignore`.
- Release для логов и ошибок (`RELEASE` = sha коммита) передаётся флагами `--env` / `--build-env`: у CLI-деплоев нет `VERCEL_GIT_COMMIT_SHA`.
- Когда истечёт срок редиректа (не раньше ~14 апреля 2027) и старый проект удалят, Лабораторию можно перевести на Git-интеграцию, включив её в `vercel.json`.
