# Публичный API только для чтения: версия в пути, OpenAPI из zod, без ключей

Статус: proposed (13 ноября 2026, grilling; `docs/stages/stage-8-public-api.md`, решения 1–4, 6–11).

Прайс, Тренеров, часы и контакты Клуба агрегаторы и виджеты сейчас могут взять только со страницы сайта. Кто-то переписывает их руками, кто-то разбирает HTML, и при правке в админке их копии расходятся с сайтом. Хостинг — 256 МБ, и сборщики данных не должны его положить.

## Решение

- **Только чтение опубликованных данных Клуба:** Клуб, Залы, Тарифы, Тренеры (без личных контактов), Направления. Отзывов, Клиентов, Записей и скрытых сущностей нет.
- **REST + JSON, версия в пути** (`/api/v1/…`). Контракт — OpenAPI 3.1, собранный из схем zod модулей; контрактный тест в CI.
- **Без ключей, с лимитом:** 60 запросов в минуту с адреса. Счётчик хранится в памяти процесса, в базу не пишется; сверх лимита — 429 с `Retry-After`. Ответы статические с ревалидацией, `revalidateSite()` сбрасывает и их.
- **Правило версий:** в `v1` поля только добавляются. Удаление или переименование — это `v2`, а `v1` живёт ещё 6 месяцев с заголовками `Deprecation` и `Sunset`.
- **Выпуск — переключателем возможности** (ADR 0026); пока Владелец не решит, API выключен.

## Considered Options

- **GraphQL.** Гибкие запросы для нескольких списков не нужны, а схема, сервер и разбор запросов стоят памяти.
- **Ключи API.** Нужны для записи и партнёров по договору; для публичного прайса это барьер без защиты — данные и так на сайте.
- **Только JSON-LD и фид на сайте.** Уже есть для поисковиков, но без версии и контракта: любая правка разметки ломает потребителей.
- **Лимит в базе.** Запись на каждый запрос к API ради счётчика — нагрузка на 256 МБ и MariaDB хостинга.

## Consequences

- У каждого поля API есть схема zod, и его удаление — уже решение о `v2`.
- На Vercel лимит в памяти считается по экземплярам. Для Лаборатории это допустимо; на hoster.kz процесс один, и лимит точный.
- В Политике появляется абзац об API и о том, что адрес запроса для лимита не хранится.
