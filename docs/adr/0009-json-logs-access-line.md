# Логи — строки JSON в stdout; строка доступа — перехватом http.ServerResponse из instrumentation.ts

Логи нужны в двух средах: на Vercel (Лаборатория) и на hoster.kz (standalone `start.cjs` → `server.js` под Passenger). Обе собирают stdout процесса, другого общего канала нет: лог-дренов на Hobby нет, на Plesk есть только журнал приложения. Формат — одна строка JSON на событие: `level`, `time`, `msg`, `release` (sha коммита), `request_id`, `route` (путь без query), `method`, `status`, `duration_ms`, при ошибке — `error` (имя и последняя строка сообщения). Поля проходят белый список (`src/lib/observability/log.ts`), поэтому IP, cookies, заголовки, тела запросов и поля форм в лог не попадают, даже если их передали по ошибке. Это проверяет тест.

`request_id` создаёт middleware: входящий `X-Request-Id` принимается, только если похож на идентификатор, иначе генерируется UUID. Id уходит дальше в заголовке запроса и возвращается клиенту в `X-Request-Id`.

**Строка доступа** пишется там, где известны статус и длительность, то есть в Node-процессе после ответа. `register()` в `src/instrumentation.ts` один раз ставит перехват:
- конец запроса — первый `end()` у `http.ServerResponse.prototype`, строка пишется на `'finish'`. Этот объект есть в обеих средах;
- начало — событие `'request'` у `http.Server.prototype` на хостинге (точное время в процессе). На Vercel обработчик Next вызывается в обход `http.Server`, поэтому начало берётся из метки `x-request-start` (`Date.now()`), которую middleware ставит на краю сети и всегда перезаписывает. Длительность на Vercel включает путь от края до функции и холодный старт. Метка старше минуты или из будущего отбрасывается.

Проверено 17 октября 2026. Прод-двойник: 73 строки за прогон, release из `release.txt`, сквозной `X-Request-Id`. Лаборатория: `/api/health` (Владелец) показал `accessLog.requests`, растущий с каждым запросом, при `serverEvents: 0` — значит, на Vercel перехват `http.Server` действительно не срабатывает и нужен путь через `ServerResponse`.

## Considered Options

- **Только middleware** — до ответа: статуса и длительности нет.
- **Свой сервер вместо `server.js`** — на хостинге возможно, на Vercel нет.
- **OpenTelemetry (спаны Next `BaseServer.handleRequest`)** — даёт статус и время в обеих средах, но тянет SDK и экспортёр: память на 256 МБ хостинга и лишняя сложность ради одной строки.
- **Логи платформы Vercel** — статус и время там есть, но без нашего `request_id` и только на Vercel.

## Consequences

- Перехват прототипов Node — зависимость от внутреннего устройства Next и Vercel. Если строки пропадут, это видно по `accessLog` в `/api/health` и в прод-двойнике.
- Статику, которую отдаёт CDN Vercel, и кэш-попадания на краю функция не видит: их строк нет (они есть в логах платформы).
- `/api/health/live` и `/_next/static/*` не пишутся, чтобы мониторинг не засорял журнал.
- `release` на хостинге — `release.txt` из сборки (`assemble.mjs`), его читает `start.cjs`; на Vercel — `RELEASE` из `vercel deploy --env` (ADR 0008).
