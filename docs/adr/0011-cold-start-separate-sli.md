# Холодный старт не прогреваем, а считаем отдельным SLI

> **25 октября 2026 частично заменён ADR 0014.** Синтетику делает UptimeRobot, холодный старт меряется по заголовку `X-Cold-Start` сразу после выкатки, а в SLO страниц входит как есть. Решение «не прогревать» и цели (Vercel ≤ 1,5 с, двойник ≤ 3 с) остаются.

Обе среды усыпляют процесс без трафика. Vercel поднимает новый экземпляр функции после выкатки и простоя, Passenger на hoster.kz останавливает приложение без запросов. Первый запрос после этого медленнее, и SLO «ответ быстрее 1 с» (`docs/runbooks/observability.md`) на нём может нарушаться.

**Замер, 17 октября 2026:**

| Среда | Холодный | Тёплый |
|---|---|---|
| Vercel `fra1`, `/api/health/ready`, первый запрос к свежему деплою (3 деплоя) | **1067 / 1081 / 1227 мс**, медиана 1081 | медиана 192–221 мс |
| Vercel, `/ru` сразу после (кэш MISS, экземпляр уже поднят) | 397–471 мс | 109–124 мс (кэш HIT) |
| Прод-двойник в CI, остановка процесса → первый `/ru` (медиана из 3, `twin:measure`) | **2,0–2,2 с**, из них ~1,4 с — запуск процесса | p50 46–65 мс |

Холодный старт стоит около +0,9 с на Vercel и около 2 с на хостинге.

**Решение.** Не прогревать, а вести холодный старт отдельным показателем:
- **Лаборатория:** после каждой выкатки `main` workflow `lab.yml` меряет первый запрос (`scripts/monitor/cold-start.mjs`) и пишет его в сводку запуска. Синтетические проверки раз в 5 минут холодные старты не исключают: они редки и честно входят в SLI доступности.
- **Прод-двойник:** `twin:measure --check` падает, если медиана «остановка → первый `/ru`» больше 5 с. Это защита от регрессии (тяжёлые импорты при старте, миграции), а не обещание пользователю.
- **Цель:** холодный старт Vercel ≤ 1,5 с, двойника ≤ 3 с. Пересматривается на этапе 5 (SLO-панель).

## Considered Options

- **Прогрев на Vercel** — cron Vercel Hobby срабатывает раз в сутки, нужен GitHub Actions чаще. Синтетика и так ходит каждые 5 минут, отдельный прогрев ничего не добавит. Новые экземпляры при масштабировании и после выкатки он всё равно не прогреет.
- **Прогрев прода** — запрещён: прод снаружи не опрашиваем (ADR 0006). Держать Passenger поднятым (`PassengerMinInstances`, время простоя пула) на виртуальном хостинге Plesk нельзя без поддержки. К тому же это 256 МБ постоянно занятой памяти.
- **Исключить холодные запросы из SLI** — снаружи их не отличить без метки от сервера. Можно добавить заголовок первого запроса процесса, но он нужен только когда холодные старты начнут съедать бюджет.

## Consequences

- Холодный старт — главный кандидат на нарушение порога 1 с. Если burn rate вырастет из-за него, сначала уменьшаем работу при запуске (ленивые импорты, Prisma), потом думаем о прогреве.
- Цифры в сводке `lab.yml` копятся с каждой выкаткой: видна динамика без отдельной инфраструктуры.
- **Неделя 17–25 октября 2026:** допущение «синтетика каждые 5 минут, холодные старты в ней редки» не выполнилось. GitHub запускал cron 5–8 раз в сутки, поэтому все 52 проверки `/api/health/ready` пришлись на холодный экземпляр (медиана 1,4 с), и доступность недели — 67,9 %. Холодный старт сразу после выкатки — 0,83–0,93 с, цель выполнена. Источник проверок пересматривается до этапа 6 — `docs/stages/stage-0-foundation.md`, «Закрытие этапа».
