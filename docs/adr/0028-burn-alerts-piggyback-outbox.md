# Тревоги выгорания бюджета: попутно из Лаборатории через outbox, этап раньше П2

Статус: proposed (13 ноября 2026, grilling; `docs/stages/stage-5-slo-alerts.md`, решения 2, 3, 5, 8–11).

Бюджет ошибок и burn rate (ADR 0014) считает `monitor.yml` раз в сутки, поэтому о быстром выгорании узнаём с опозданием до суток. Cron GitHub для частых запусков ненадёжен: в первый день `*/5` не сработал ни разу, а суточный monitor.yml опоздал на 8 часов. На hoster.kz планировщика нет, а прод мы не мониторим. На Vercel экземпляров несколько, и состояние в памяти разойдётся.

## Решение

- **Падение адреса** присылает сам UptimeRobot: встроенная интеграция с Telegram, сразу.
- **Выгорание бюджета** считает Лаборатория попутно после `/api/health/ready` (его UptimeRobot дёргает каждые 5 минут), не чаще раза в 15 минут. Журнал берётся через API UptimeRobot по ключу «только чтение», расчёт — тот же `scripts/monitor/sli.mjs`, пороги — из ADR 0014.
- **Тревога — событие outbox** (ADR 0017) типа `alert.*` с ключом окна. Событие с тем же ключом за последний час второй раз не ставится. Отправщик ведёт `alert.*` в отдельный чат «Дежурство». Повторы и «недоставленные» работают как у Записей, новой таблицы нет.
- **API UptimeRobot молчит** — тревога «мониторинг слеп», не чаще раза в 6 часов.
- **Политика бюджета:** если бюджет исчерпан, в Лабораторию идут только PR про надёжность. В CI видна плашка, мерж она не блокирует.
- **Порядок карты:** этап 5 идёт раньше П2, потому что ему не нужна схема базы.

## Considered Options

- **Cron GitHub каждые 15 минут.** Опаздывает на часы — это и есть исходная проблема.
- **Webhook UptimeRobot на наш адрес.** На бесплатном плане ненадёжен по наличию и не считает burn: сообщает только о падении адреса.
- **Отдельная таблица состояния тревог.** Чище по смыслу, но это миграция на неделе П1. Outbox уже даёт ключ, повторы и «недоставленные».
- **Внешний сервис дежурств (PagerDuty, Opsgenie).** Платно, и для одного разработчика избыточно.

## Consequences

- В Лаборатории появляется ещё один секрет — `UPTIMEROBOT_READ_KEY` — и ещё один чат — `TELEGRAM_ALERT_CHAT_ID`.
- Модуль `notifications` различает чаты по типу события.
- Если Лабораторию никто не посещает и UptimeRobot не дёргает `/ready`, тревоги не считаются. Тогда сработает «мониторинг слеп» или суточный `monitor.yml`.
