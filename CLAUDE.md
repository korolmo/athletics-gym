## Принятые решения по сайту
- Одна страница, `/ru` (по умолчанию) и `/kk`; казахский текст необязателен — если пуст, показываем русский.
- Целевое действие — Обращение: нажатие на кнопку связи (WhatsApp с текстом про Пробное посещение, телефон, Instagram). Форм заявок нет.
- Цены на главной — только реальные, из прайса Владельца (`docs/owner/prices-2026-10.md`), по Залам: переключатель «Общий зал / Женский зал»; «от» = минимум по Категории тарифа. Тренеры — реальные, фото — карточка-плакат целиком (`public/trainers/`); запись — через WhatsApp зала. Расписания и групповых занятий нет.
- Рейтинг 2ГИС — бейдж «5,0 · 405 оценок в 2ГИС» со ссылкой; тексты отзывов из 2ГИС сами не копируем — их слово в слово переносит Владелец (этап 5). Чужие фото не используем.
- Админка: только Владелец. Аккаунт Владельца — в базе (этап 1): первый вход по `ADMIN_LOGIN` / `ADMIN_PASSWORD` его создаёт, дальше пароль меняется в разделе «Аккаунт»; версия сессии — в аккаунте. Тарифы с фильтром по Залу и Тренеры с их Тарифами (этап 0); раздел «Сайт» — Настройки сайта и показ Блоков (этап 1); раздел «Фото» (этап 2); раздел «Направления» (этап 4); раздел «Отзывы» (этап 5); главная админки — сводка Обращений (этап 6).
- Тексты и контакты главной, которые меняет Владелец, — в Настройках сайта (база; начальные значения — `src/lib/domain/site-settings.defaults.ts`), секции получают их как `s`. В словарях (`src/dictionaries`) — только подписи из кода. Номер WhatsApp, телефон и Instagram в коде не хранятся.
- Фото (этап 2, с этапа 8 — ADR 0004): файлы на диске хостинга в `MEDIA_DIR` (вне папки приложения; по умолчанию `../media`), драйвер `STORAGE_DRIVER=local`; драйвер `supabase` (ADR 0002) оставлен на срок отката, до 15 ноября. В базе только путь Фото (`gallery/<uuid>.webp`), адрес — `/media/<путь>` (раздаёт `src/app/media`, кэш на год). Работа с хранилищем — только `src/lib/storage/client.ts`. Загрузка: сжатие в браузере + копии 400 и 800 px по ширине (`<uuid>-w400.webp`) → пути от сервера (`requestUpload`, лимит объёма `MEDIA_QUOTA_MB`, 500 МБ) → каждый файл `PUT /api/admin/media/<путь>` (сессия Владельца, своя страница, до 5 МБ, тип по первым байтам, без перезаписи) → путь в базу. Файл без записи в базе не остаётся (замена, удаление, сбой записи, уборка — вместе с копиями). Не загружено — картинки из `public/`. Оптимизатора next/image на сервере нет: `src/lib/image-loader.ts` подставляет копии Фото и копии `public/` из `public/_img` (собирает `npm run images:build` перед dev и build); логотипы — объекты с путём в `src/lib/brand.ts`, не импорт файла. Подробности — `docs/deploy.md`, «Хранилище фото на hoster.kz».
- Отзывы (этап 5): только настоящие — придуманных и демо-отзывов нет, seed их не создаёт. Отзыв Посетителя с сайта получает Статус «Новый» и не виден до решения Владельца; его текст Владелец не правит (только опубликовать, скрыть, удалить). Ручной Отзыв Владельца сразу опубликован. На сайте — только опубликованные; пока их нет, от Блока «Отзывы» остаются рейтинг 2ГИС и кнопка «Оставить отзыв» (пустой секции нет). Текст Отзыва не переводится и выводится только как текст. Антиспам формы без капчи: поле-ловушка, не быстрее 3 секунд с открытия формы (метка времени подписана `AUTH_SECRET`, выдаётся при открытии формы), 3 Отзыва в сутки с адреса (хэш IP). Телефон и почту Посетителя не собираем. Правила — `src/lib/domain/review.ts`.
- SEO (этап 6): адрес сайта — только из `SITE_URL` (`src/lib/seo.ts`, по умолчанию `https://athleticsgym.kz`); в коде адрес не пишем. Метаданные, robots, sitemap и JSON-LD строятся чистыми функциями из `src/lib/seo.ts`. Индексируется только production — `APP_ENV` (запасная `VERCEL_ENV`): иначе `noindex` и `Disallow: /`; `X-Robots-Tag` вычисляется при сборке (ветку `deploy` собирают с `APP_ENV=production`). В JSON-LD (ExerciseGym) нет и не должно быть `aggregateRating` и отзывов: рейтинг взят из 2ГИС. Картинка-превью (`opengraph-image`) читает шрифты и логотип с диска: каждый такой файл должен быть в `outputFileTracingIncludes` в `next.config.mjs`, иначе standalone-сборка его не возьмёт и маршрут отдаст 500; после выкатки открывать его на боевом сайте.
- Обращения (этап 6): счётчик нажатий на кнопки связи без персональных данных — не храним IP, не ставим cookies, сторонней аналитики нет. Ссылки помечать не нужно: `ContactTracker` сам определяет Канал по адресу ссылки и Источник по секции (или по `data-contact-source`). Новое место с кнопкой связи вне секций — добавить Источник в `src/lib/domain/contact.ts`. Запись — `POST /api/contact`, переход по ссылке её не ждёт.
- Направления (этап 4): список ведёт Владелец (раздел «Направления»), в словарях их больше нет. Картинка — иконка из набора (`src/lib/domain/direction.ts`, рисунки — `src/components/site/direction-icons.tsx`) или своё Фото через загрузку этапа 2 (место `direction:<id>`). На сайте — только не скрытые, в заданном порядке; без них Блока нет.
- Кэш главной (этап 7): `/ru` и `/kk` — статические страницы с ревалидацией, не `force-dynamic`. Страница собирается при первом запросе (при сборке база не нужна — `generateStaticParams` пуст) и лежит в кэше; каждое сохранение в админке вызывает `revalidateSite()` (`src/lib/admin/revalidate.ts`) — правка видна сразу; запасной срок — час (`revalidate = 3600`). Новое действие админки, меняющее сайт, обязано вызвать `revalidateSite()`. В страницу нельзя запекать то, что зависит от запроса или времени: метку формы отзыва выдаёт серверное действие `openReviewForm` при открытии формы, счётчик Обращений идёт отдельным запросом. Правка базы мимо админки (seed, SQL) на сайте появится в течение часа или после нового деплоя.
- Контраст (этап 7): текст — не ниже 4,5:1 (WCAG AA). На зелёном WhatsApp текст и значок тёмные (`text-on-whatsapp`), белый не использовать; приглушённый текст — `text-text-muted` / `text-muted` без прозрачности; ссылка внутри текста — с подчёркиванием. Проверка — axe по сайту и админке, Lighthouse Accessibility = 100.
- Бегущая строка (11 октября): лента под первым экраном — Блок `marquee`, его пункты — в Настройках сайта (`marqueeRu` / `marqueeKk`, списки одной длины; пустой казахский пункт — «как на русском»). До 8 пунктов по 40 символов; `{часы}` и `{рейтинг}` сайт заменяет часами работы и оценкой 2ГИС из Настроек, другие фигурные скобки форма не принимает. Правила — `marqueeItems` и `hasUnknownPlaceholder` в `src/lib/domain/site-settings.ts`; вид — `sections/Marquee.tsx` (Oswald, ★ между пунктами, наклон −2°, лента шире экрана; число повторов и длительность считаются по длине текста отдельно для телефона, планшета и широкого экрана; вне экрана лента стоит).
- Юридические страницы (этап 9): `/ru|kk/privacy` и `/ru|kk/terms`; тексты — данные в `src/lib/legal` (`privacy.ts`, `terms.ts`, RU и KZ), страница их только выводит. **В Политике конфиденциальности — только то, что сайт делает на самом деле**: поменяли, что и сколько хранится, какие cookie или сторонние сервисы, — в той же ветке поправить текст и дату редакции (`LEGAL_UPDATED` в `legal/meta.ts`). Сроки и лимиты в тексты подставляются из констант кода (`legal/facts.ts`), вручную их не пишем. Реквизиты (название ИП, ИИН/БИН — 12 цифр, юр. адрес, email) и место хранения данных — в Настройках сайта, форма «Реквизиты» раздела «Сайт»; это не Блок и не скрывается. Пока Реквизиты пусты, в подвале только ссылки на документы. Тексты документов Владелец не правит: это код, перед изменением — к юристу.
- Согласие на обработку данных (этап 9): галочка в форме Отзыва обязательна — проверяют браузер (`required`), разбор формы (`parseVisitorReview`) и сервис (`createVisitorReview` без согласия бросает ошибку). С Отзывом хранится время Согласия и дата редакции Политики (`consentAt`, `consentPolicyDate`); у ручных Отзывов пусто.
- Cookie и сторонние сервисы (этап 9): сайт ставит только cookie языка (`src/lib/locale-cookie.ts`) и сессии Владельца. Сообщение о cookie (`CookieNotice`) помнит «Понятно» в localStorage, не в cookie; стоит поверх страницы и на телефоне — над нижней панелью. Карта в «Контактах» (OpenStreetMap) грузится только по нажатию «Показать карту» (`contacts/MapPanel.tsx`): до нажатия сайт к стороннему сервису не обращается. Новый сторонний сервис на сайте (карта, видео, виджет) — только по нажатию и с записью в Политике.
- Скорость главной (12 октября, ветка perf-95). Шрифты сайта — два семейства, каждое одним своим файлом в `src/assets/fonts/site` (Onest 400–800 и Oswald 600, только нужные знаки; как собраны — README там же), подключены через `next/font/local` в `src/lib/fonts.ts`; шрифты админки — отдельно, в `src/lib/admin-fonts.ts`: из общего файла Next предзагружал публичным страницам и их (девять файлов вместо одного). Текст сайта — Onest, а не Manrope из макета: в Manrope нет Қ Ғ Ұ Ә Ң и ₸, их рисовал системный шрифт; у Onest и Oswald казахский набор полный (новый шрифт сайта проверять на эти буквы через fonttools). Картинка-превью ссылок рисуется тем же Onest (`src/assets/fonts`). Блоки ниже первого экрана — с `content-visibility: auto` и оценкой высоты `--est` (globals.css): поменялась высота блока заметно — поправить оценку. Из-за этого окна поверх страницы (плакаты) рисуются порталом в `body`, а перед переходом по якорю `Motion.tsx` ставит `data-full-layout` — страница раскладывается целиком, и ссылка меню попадает точно. Блоки главной в `<Suspense>` не оборачиваем: React отдаёт большие границы скрытыми и вставляет их скриптом — без скриптов страница осталась бы пустой. Текст первого экрана не начинает с `opacity: 0` (только сдвиг). Фото первого экрана предзагружается только с 1024 px: на телефоне оно ниже первого экрана. Иконки вкладки — маленькие копии логотипа (`siteIcons` в `src/lib/brand.ts`). Локальная сборка на Windows не ставит предзагрузку шрифтов (ошибка Next с путями), поэтому её замеры отличаются от Vercel — см. `docs/deploy.md`, «Замер скорости».
- Движение (этап 7): только CSS (keyframes, transition) и IntersectionObserver, без библиотек; анимируем только `transform` и `opacity`. Размытие (`filter: blur`, `backdrop-blur`) на телефоне не используем: свечение рисуем градиентом, у закреплённых плашек (шапка, нижняя панель) фон плотнее, а `backdrop-blur` — только с префиксом `md:`. У `next/image` с `fill` и у картинок крупнее 64 px всегда задаём `sizes` по реальной ширине в сетке. Стили — блок «Движение» в `globals.css`, целиком под `prefers-reduced-motion: no-preference`; скрипт — `src/components/site/motion-run.ts`, его подгружает `Motion.tsx` отдельным файлом после оживления страницы. Сервер отдаёт страницу готовой: без скрипта и при «меньше движения» всё видно сразу; скрытое до появления состояние ставит только скрипт и только тому, что ниже экрана. Встроенных скриптов в `<head>`/начале `<body>` не добавляем — это сдвигает первую отрисовку (проверено Lighthouse). Девиз на телефоне: каждая часть (`splitMotto`) — с новой строки, чтобы число строк не зависело от загрузки шрифта (иначе CLS). Шрифты, которые не нужны первому экрану, включаем после загрузки страницы (`data-late-fonts` в `motion-run.ts`): Oswald бегущей строки, загруженный сразу, сдвигал первую отрисовку на 0,45 с. Новый блок карточек получает появление и наведение сам, если у карточки есть `data-card`.
- Страницы ошибок (23–24 октября, ADR 0013) — по макетам Stitch, промпты в `design/STITCH-BRIEF.md`; тексты — `src/dictionaries/errors` (раздел `errors` словарей; отдельный файл, потому что его берёт клиентская `app/global-error.tsx`). **404** — `app/global-not-found.tsx` (флаг `experimental.globalNotFound`): Next отдаёт его любому адресу без маршрута с кодом 404 и готовым HTML, на hoster.kz и Vercel одинаково; страница статическая и одна на все адреса — обе языковые версии в HTML, язык выбирает браузер (адрес `/kk/…` или cookie), без базы. `notFound()` внутри страницы не годится: Next (15.5 и 16.4, даже с одним корневым layout) рисует его только в браузере. Адрес без языка: `/`, `/privacy`, `/terms` (`LOCALE_REDIRECTS` в middleware) — переадресация на язык из cookie, любой другой — сразу 404 (middleware переписывает под `/ru` без кода). **Middleware не переписывает адрес с кодом ошибки** (`rewrite(url, { status })`): Vercel подменяет такой ответ своей страницей. **503** — `MAINTENANCE_MODE=1`: middleware сам отдаёт готовую двуязычную страницу (`offlinePage("maintenance")`) с `Retry-After`; статическая `public/errors/503.html` для веб-сервера — `npm run errors:build` (тест сверяет), подключение в Plesk — `docs/hosting-plesk.md`, раздел 10, ещё не сделано. **500** статических страниц — `src/pages/500.tsx` (код 500, мимо кэша), ошибки в браузере и упавший layout — `app/global-error.tsx`; **своей `error.tsx` у сайта нет и не добавлять**: при сбое базы Next кладёт её в ISR-кэш как `/ru` с кодом 200. Админка — `<Suspense>` в `(protected)/layout.tsx` и её `not-found`/`error` (код 200). Номер зала на страницах ошибок не показываем — контакты в 2ГИС. Память страниц ошибок меряет прод-двойник (фаза ошибок в `npm run twin:measure`); поведение Vercel — смоук после каждой выкатки Лаборатории (`scripts/lab/smoke.mjs` в `lab.yml`, маркер `data-error-page`).
