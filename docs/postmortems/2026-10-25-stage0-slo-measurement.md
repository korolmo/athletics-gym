# Замер SLO этапа 0 оказался невалидным: мерили редкость cron, а не доступность

Статус: закрыт · Среда: Лаборатория · Дата разбора: 13 ноября 2026 (задним числом; решение — ADR 0014 от 25 октября)

## Кратко
Неделя этапа 0 (17–25 октября) закончилась доступностью 67,9 % при цели 99,5 %. Сайт при этом работал: страницы `/ru` и `/kk` ответили 200 в 104 случаях из 104. Число получилось из-за измерителя. Синтетика на cron GitHub Actions запускалась в 40 раз реже плана, и каждая проверка `/api/health/ready` попадала на холодный экземпляр.

## Влияние
- Пользователи Лаборатории — никакого: сбоев не было.
- Проект: SLO недели «не выполнен», этап 0 закрыт с долгом. Тревога выгорания не могла сработать ни разу: требовала 18 проверок в час, а было не больше 3.

## Хронология (UTC)
- 17.10 17:11 — включён мониторинг: cron `*/5 * * * *`, 3 проверки за прогон.
- 17.10–25.10 — 52 прогона вместо ~2300; медиана интервала — 201 минута (данные ветки `monitoring`).
- 25.10 06:58 — отчёт недели: 67,9 %, burn 30 д — 64; все 52 проверки `/ready` — холодные (медиана 1,4 с против 0,2–0,4 с у тёплого).
- 25.10 — разбор, ADR 0014: проверки делает UptimeRobot, SLO — только по страницам, холодный старт — отдельный SLI.

## Причина
Источник проверок выбрали по удобству (всё в GitHub), не проверив его частоту. Cron GitHub Actions не гарантирует расписание и на бесплатных раннерах сильно опаздывает. В SLI попала диагностическая проверка `/api/health/ready`: на редком опросе она всегда холодная, а это отдельное свойство (ADR 0011).

## Что сработало и что нет
- Сработало: сырые проверки сохранялись в `data/*.jsonl`, поэтому причину нашли по данным, а не догадкой.
- Не сработало: «мониторинг мониторинга» был, но мерил долю проверок за сутки только после отчёта, а отчёт шёл тем же ненадёжным cron.

## Что меняем
| Действие | Зачем | PR / статус |
|---|---|---|
| Проверки — UptimeRobot каждые 5 минут, мониторы из репозитория | Частота не зависит от cron | ADR 0014, сделано |
| SLO — только `/ru` и `/kk`; `/ready` — диагностика | Не мерить холодный старт как доступность | ADR 0014, сделано |
| Холодный старт — отдельный SLI сразу после выкатки | Свойство платформы видно отдельно | ADR 0011, 0014, сделано |
| Тревоги — попутно из Лаборатории, не cron | Узнавать за минуты, а не за сутки | ADR 0028, этап 5, PR #114 |

## Уроки
- Проверять сам измеритель: сколько замеров он реально дал, — до того, как смотреть на цифру.
- Cron GitHub Actions — не планировщик для частых задач. Это повторилось на этапе 1: `*/5` очереди уведомлений не сработал ни разу, решение — попутный запуск.
