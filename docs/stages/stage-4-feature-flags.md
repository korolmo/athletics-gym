# Этап 4: переключатели возможностей (план)

Начат 13 ноября 2026 (grilling, решения 1–13, везде принят рекомендованный вариант). Инженерная суть из `docs/engineering-roadmap.md`: feature flags (по желанию, после этапа 5). Термины — `GLOSSARY.md`.

## Решения

| # | Вопрос | Решение | Почему |
|---|---|---|---|
| 1 | Зачем | **Выпуск без выкатки и аварийные выключатели.** Готовый код уходит выключенным и включается, когда решат: в Лаборатории — для показа, на проде — Владелец. Выключатели гасят тяжёлое (кабинет, отправку уведомлений, сброс демо) быстрее отката тега. Доли Посетителей и A/B — нет | Прод заморожен, выпуск — по решению Владельца; на 256 МБ выключить быстрее, чем откатить. A/B на трафике одного зала статистически пуст |
| 2 | Где живут | **В базе, у Клуба:** таблица `FeatureFlag` (Клуб, ключ, включён, кто и когда переключил). Переменные окружения остаются для того, что про среду: `APP_ENV`, `MAINTENANCE_MODE`, запреты прода (демо-канал кода, гостевой вход) | «Без выкатки» и «по Клубу» (П2) дают только данные; внешний сервис — сторонний вызов, Политика, деньги |
| 3 | Кто переключает | **Флаги выпуска — Владелец** в админке (раздел «Возможности» в меню «Ещё»). **Выключатели и технические — разработчик:** скрипт в Лаборатории, SQL по runbook на hoster.kz. Каждое переключение — событие журнала действий (этап 2) | Выпуск — решение Владельца, авария — дело дежурного; роли «разработчик» в админке нет |
| 4 | Чтение и кэш главной | **Все флаги Клуба — одним запросом, в React `cache` на запрос.** Флаг, влияющий на главную, при переключении вызывает `revalidateSite()`. В сборку не запекаются; proxy (middleware) их не читает — у него нет базы | Тот же путь, что у Настроек сайта: правка → сброс кэша |
| 5 | Когда код | **После этапа 2** (переключение сразу пишется в журнал). Если П2 понадобится включать второй Клуб по частям, PR 1 (таблица и чтение) поднимается раньше | Этап по желанию, после 5 |
| 6 | Список флагов | **Закрытый реестр в коде** (`src/modules/flags/domain/registry.ts`): ключ, вид (выпуск или выключатель), описание для админки, кто переключает, значение по умолчанию, дата «убрать до». Строки базы с неизвестным ключом игнорируются. На старте: выпуск — личный кабинет, форма Отзыва, будущая Цена тарифа (этап 3); выключатели — новые Записи, отправка уведомлений, суточный сброс демо | Флаги-строки без кода — путь к опечаткам и забытым ключам |
| 7 | Значение без строки или при сбое базы | **Значение по умолчанию из реестра.** Выключатель по умолчанию — «работает»; флаг выпуска — «выключен» | Сбой чтения не должен ни гасить работающее, ни включать невыпущенное |
| 8 | Флаги и прод | **Миграция заводит строки флагов выпуска выключенными;** выкатка релиза ничего нового не включает без решения Владельца. В Лаборатории `seed:lab` их включает | Совпадает с правилом «изменения попадают к клиенту только по решению Владельца» |
| 9 | Долг флагов | **У флага выпуска — дата «убрать до»:** через два релиза после включения на проде флаг и ветка «выключено» удаляются из кода. Тест падает, если дата прошла | Флаги, которые живут вечно, превращают код в лабиринт `if` |
| 10 | Где проверяется | **Только на сервере:** страницы, действия, API, сервисы. Клиентские компоненты получают результат пропом. Выключенная возможность: страница — «Временно недоступно» с кодом 503 и `Retry-After` (не 404 и не 500), действие — понятная ошибка | Проверка в браузере обходится; 503 — честный ответ «временно» для мониторинга и поисковиков |
| 11 | Измерения | Время от решения до включения: **секунды без выкатки** (было: выкатка или перезапуск). Переключателей из окружения перенесено в реестр: число «до/после». Тест: каждый выключатель гасит своё без 5xx. Game day в Лаборатории: выключить отправку уведомлений под нагрузкой двойника — очередь копится, после включения уходит | DoD этапа |
| 12 | Решения | **ADR 0026** — переключатели в базе по Клубу, закрытый реестр, значения по умолчанию, срок жизни флага | Чтобы «ещё одна переменная окружения» не стала привычкой |
| 13 | Термины | **«Переключатель возможности»** — флаг выпуска, которым Владелец включает готовую возможность; **«Аварийный выключатель»** — флаг, которым дежурный гасит тяжёлую часть сайта | В GLOSSARY |

Решения оформлены в ADR [0026](../adr/0026-feature-flags-in-db.md).

## Список PR (черновик)

Каждый PR — короткая ветка, мерж только по слову Владельца репозитория. Код — после этапа 2.

1. **Модуль `flags`:** реестр, таблица `FeatureFlag` с `clubId`, чтение одним запросом, значения по умолчанию, тест «убрать до».
2. **Выключатели:** новые Записи, отправка уведомлений, сброс демо — проверка в сервисах, страница «Временно недоступно» (503); скрипт переключения в Лаборатории и runbook для hoster.kz.
3. **Флаги выпуска и раздел «Возможности»:** личный кабинет, форма Отзыва, будущая Цена тарифа; `revalidateSite()` при переключении; событие журнала.
4. **Закрытие:** game day, замер «после», ретро.
