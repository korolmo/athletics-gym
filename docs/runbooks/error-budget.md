# Политика бюджета ошибок Лаборатории

Этап 5, решение 5; ADR 0014 (SLO и бюджет), ADR 0028 (тревоги). Только Лаборатория: боевой сайт не мониторится (ADR 0005).

## Что считаем

- **Два SLO** (поправка к ADR 0014 от 13 ноября), проверки — UptimeRobot каждые 5 минут:
  - **доступность** — 99,5 % проверок страниц `/ru` и `/kk` за 30 дней с ответом 200 и первым экраном; бюджет — 0,5 % (при 2 × 288 проверках в сутки за 30 дней около 86 сбоев);
  - **скорость** — 95 % проверок быстрее 1 с; бюджет — 5 %.
- **Остатки** — на странице статуса и в `status.json` (`budget.remaining` и `speed.budget.remaining`): 1 — бюджет цел, 0 — исчерпан, меньше 0 — перерасход. Политика ниже действует, если исчерпан **любой** из двух.

## Правила

1. **Остаток ≥ 0 — обычная работа.**
2. **Любой остаток < 0 — в `main` (и значит в Лабораторию) идут только PR про надёжность**, пока остаток снова не станет ≥ 0. Про надёжность:
   - исправление причины ошибок SLO;
   - мониторинг, тревоги, замеры, постмортемы;
   - CI и документы;
   - уборка и обновления зависимостей без изменения поведения сайта.

   Новые возможности (кабинет, админка, сайт) ждут.
3. **Исключение** — по решению Владельца репозитория: в описании PR строка «Бюджет исчерпан, исключение: <почему>».
4. **Сработала тревога быстрого выгорания** — постмортем в `docs/postmortems/` в течение недели (шаблон там же).
5. **Проверка в CI информационная:** шаг «Бюджет ошибок» показывает остаток в отчёте каждого PR и не блокирует мерж. Проект ведёт один человек: блок мешал бы чинить, а видимость и записанное правило дают дисциплину.
