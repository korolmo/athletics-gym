# Athletic's Gym — сайт реального клуба и платформа для любого клуба

> Лендинг проекта, обновлён 12 ноября 2026. Термины — [GLOSSARY.md](./GLOSSARY.md), решения — [docs/adr](./docs/adr), план — [docs/engineering-roadmap.md](./docs/engineering-roadmap.md).

**Реальный клиент.** Athletic's Gym в Кызылорде: два Зала (общий и женский) и сайт на русском и казахском. В админке Владелец с телефона ведёт Тарифы, Тренеров, Фото, Отзывы и тексты. Боевой сайт **https://athleticsgym.kz** работает на хостинге в Казахстане (hoster.kz, 256 МБ памяти) и заморожен на релизе **`v1.0.0`**. Новые версии попадают к клиенту только по решению Владельца.

**Лаборатория.** Тот же код развивается в платформу для любого Клуба: **https://athletics-gym-lab.vercel.app**.
- **Данные.** Бренд, тексты и Тарифы — от Athletic's Gym. Тренеры, Клиенты, Записи, Отзывы и Обращения — вымышленные, личных данных нет.
- **Выкатка.** `main` выкатывается автоматически, каждый PR получает превью со своей базой.
- **Статус и SLO** — **https://korolmo.github.io/athletics-gym/**.

## Архитектура

```mermaid
flowchart LR
  dev["PR → main"] --> ci["CI: тесты на MariaDB 10.4,\nграницы модулей, сборка,\nпрод-двойник 256 МБ"]
  dev --> lab["Лаборатория\nVercel fra1 · TiDB · Supabase Storage"]
  tag["тег vX.Y.Z +\nподтверждение Владельца"] --> deploy["ветка deploy"] --> prod["Прод: hoster.kz\nPlesk · Node 23 · MariaDB 10.4"]
  mon["UptimeRobot каждые 5 мин"] --> lab
  mon --> pages["страница статуса"]
  lab -. ошибки .-> sentry["Sentry"]
  lab -. Записи .-> tg["Telegram Владельца\n(outbox)"]
```

Подробно — C4 контейнеров: [docs/architecture/containers.md](./docs/architecture/containers.md).

- **Один Next.js-проект** на сайт, кабинет и админку: Next 16 (App Router, standalone, Turbopack), TypeScript, Tailwind 4, Prisma 6 (переход на Prisma 7 готов).
- **Модули по сущностям** (ADR 0015): `src/modules/<имя>` со слоями `domain` → `validation` → `service`. Снаружи модуль доступен только через `index.ts` и `client.ts`, чужие таблицы — только через модуль-хозяина. Границы проверяет dependency-cruiser в CI.
- **Две среды, один код.** Vercel (serverless) и виртуальный хостинг без SSH и Docker. Совместимость с продом проверяет прод-двойник в CI: те же 256 МБ и 1 CPU, MariaDB 10.4, запуск через `start.cjs` с миграциями.
- **Гарантии у базы** (ADR 0017):
  - двойную Запись на одно Окно запрещает уникальный индекс;
  - повтор формы распознаётся по ключу повтора;
  - лимит Записей держит блокировка строки Клиента.
- **Уведомления через transactional outbox.** Событие пишется в одной транзакции с Записью, у отправки есть повторы и dead-letter. Отправка идёт попутно, после ответов: на хостинге нет планировщика, а cron GitHub опаздывает на часы.
- **Клуб — это данные** (ADR 0018). Название, город, логотип, цвет акцента с правилом контраста WCAG и часовой пояс берутся из базы. Второй Клуб — этап П2 (ADR 0020–0021).
- **Наблюдаемость.** JSON-логи с `request_id` и строкой доступа, `/api/health/live|ready`, ошибки в Sentry, проверки UptimeRobot с бюджетом ошибок, холодный старт по заголовку `X-Cold-Start`. Всё это только в Лаборатории: прод снаружи никто не опрашивает.

## Что умеет

- **Сайт** `/ru`, `/kk`:
  - разделы: первый экран, бегущая строка, о зале, Направления, Женский зал, цены по Залам («от» — минимум по Категории тарифа), Галерея, Тренеры с персональными Тарифами, Отзывы, контакты с картой по нажатию;
  - целевое действие — Обращение (WhatsApp, телефон, Instagram); счётчик Обращений без персональных данных.
- **Личный кабинет Клиента** (только Лаборатория):
  - вход по телефону и одноразовому коду;
  - запись к Тренеру в свободное Окно по его часам работы;
  - «Мои Записи», отмена в установленный срок, Согласие на обработку данных.
- **Админка** `/admin` (Владелец):
  - Записи по дням и Тренерам, недоставленные уведомления со сводкой доставки;
  - Тарифы, Тренеры с часами работы и исключениями;
  - Настройки сайта и показ Блоков, форма «Клуб» (название, город, цвет, логотип);
  - Фото (сжатие в браузере, копии 400 и 800 px), Отзывы (модерация и ручные), Направления;
  - сводка Обращений, Реквизиты, аккаунт и «выйти на всех устройствах».
  - В Лаборатории — гостевой вход: всё, кроме Фото, аккаунта и удалений.
- **Качество:**
  - WCAG AA; движение только на CSS и IntersectionObserver;
  - кэш главной со сбросом при каждом сохранении в админке;
  - SEO с hreflang и JSON-LD;
  - Политика конфиденциальности и Пользовательское соглашение на двух языках;
  - CSP и заголовки безопасности.

## Запуск (Windows, PowerShell)

Нужны Node.js 22+ и Docker Desktop.

```powershell
npm run db:up            # MariaDB 10.4 в Docker (порт 3307)
copy .env.example .env   # задать ADMIN_LOGIN, ADMIN_PASSWORD, AUTH_SECRET
npm install
npm run db:migrate
npm run seed             # Залы, Тарифы, Тренеры из прайса Владельца; на APP_ENV=production откажется
npm run dev              # http://localhost:3000, кабинет — /ru/cabinet, админка — /admin
```

| Команда | Что делает |
|---|---|
| `npm run lint` · `npm run typecheck` · `npm run deps:check` · `npm test` · `npm run build` | Проверки перед коммитом (CI делает то же) |
| `npm run build` → `node scripts/standalone/assemble.mjs` → `npm run twin:measure` | Прод-двойник: пакет для хостинга в Docker с лимитами hoster.kz; RSS, p50/p95, холодный старт |
| `node scripts/twin/history.mjs` | Медианы прод-двойника по прогонам CI на `main` — для замеров «до/после» |
| `npm run seed:lab` | Данные Лаборатории (TiDB, из `.env.lab`) |
