# Runbook: демо-админка Лаборатории (Гость и суточный сброс)

Только **Лаборатория** (https://athletics-gym-lab.vercel.app). На боевом сайте гостевого входа и сброса нет и быть не может: оба работают только при `APP_ENV=lab` (тест). Решения — `docs/stages/stage-p1-brand.md` (П1, решения 6–11, 15, 17–20), ADR 0018–0019.

## Как устроено

- **Вход.** `/admin/login` → «Войти как гость»: без пароля, сессия 2 часа, та же cookie `ag_admin` с ролью `guest` в подписи. Кнопка есть, только если `APP_ENV=lab` и `GUEST_DEMO=1`. «Выйти на всех устройствах» Владельца закрывает и гостевые сессии.
- **Что Гостю закрыто** — `requireRealOwner` (список и тест — `src/app/admin/guest-locked.test.ts`): Фото (загрузка, удаление), «Аккаунт», удаление сущностей, ручные Отзывы, Реквизиты, часы Тренеров, отмена Записей, уведомления, снимок демо. Загрузка файла `PUT /api/admin/media` — 403. Номера Клиентов Гостю не отдаются.
- **Сброс.** Модуль `src/modules/demo`, таблица `DemoState`. Первый запрос после включения снимает исходное состояние; дальше раз в сутки после 04:00 по времени Клуба Клуб, Настройки сайта, Тренеры, Тарифы, Направления, статусы Отзывов и Галерея возвращаются к снимку; созданное после снимка удаляется. Запуск попутный (`src/app/demo-reset-kick.ts`): после `/api/health/ready` (UptimeRobot, каждые 5 минут), кабинета и админки. Блокировка — 5 минут.
- **Где видно.** Админка → «Сайт» → «Демо Лаборатории»: время снимка, последнего сброса и его длительность. Лог: `Демо Лаборатории: сброс к снимку за N мс`.

## Включить / выключить

- **Включить** (после закрытия этапа 1): переменная проекта Vercel `athletics-gym-lab` → Production → `GUEST_DEMO=1`, затем выкатка `main` (`gh run rerun <id>` последнего «Lab (Vercel)» по `push`). Первый же запрос снимет снимок — **до этого приведите Лабораторию в исходный вид** (бренд Athletic's Gym, настоящие тексты).
- **Выключить**: убрать `GUEST_DEMO` и перевыкатить. Кнопка гостя пропадёт, сброс перестанет запускаться, выданные гостевые сессии доживут до своего срока (до 2 часов) — закрыть сразу: Владелец → «Аккаунт» → «Выйти на всех устройствах».
- **Превью PR** — `GUEST_DEMO=1` всегда (`lab.yml`): у превью своя база.

## Что делать, если…

| Сигнал | Действия |
|---|---|
| Гость «сломал» сайт (неприличный текст, странное название) | Не ждать 04:00: Владелец открывает «Сайт» → «Клуб» и нужные формы и возвращает вручную. Если повторяется — выключить `GUEST_DEMO` |
| Сброс не прошёл ночью («последний сброс» — вчерашний) | Проверить, что UptimeRobot зовёт `/api/health/ready` (страница статуса). Посмотреть лог «Демо Лаборатории: попутный сброс не удался». Сброс повторится сам через 5 минут после сбоя |
| Владелец поменял Лабораторию и хочет, чтобы так и осталось | «Сайт» → «Демо Лаборатории» → «Сделать текущее состояние исходным» |
| Пропали Тренер или Тариф, созданные Владельцем | Их создали после снимка — сброс считает их правкой Гостя. После правок Владельца — сразу «Сделать текущее состояние исходным» |
| Записи Клиентов к удалённому сбросом Тренеру исчезли | Тренер был создан после снимка (Гостем). Записи этапа 1 так не теряются, если Тренеров не создавать без нового снимка |
| Сброс идёт долго (сотни мс → секунды) | Число строк выросло: время — в «Демо Лаборатории» и в логе; это одно из измерений этапа П1 |

## Чего не делать

- Не включать `GUEST_DEMO` на боевом сайте — он не сработает (`APP_ENV=production`), но и смысла нет: Гость правил бы настоящий сайт.
- Не открывать Гостю новое опасное действие: новое действие админки по умолчанию — `requireOwner` (Гостю можно), опасное — `requireRealOwner` и строка в `guest-locked.test.ts`.
- Не добавлять в снимок Клиентов, Записи, уведомления и Обращения — это данные замеров.
