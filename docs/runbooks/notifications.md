# Runbook: уведомления Владельцу (Telegram)

Только **Лаборатория** (https://athletics-gym-lab.vercel.app): на боевом сайте кабинета и уведомлений нет (ADR 0016). Решение — ADR 0017, код — модуль `src/modules/notifications`.

## Как устроено

- Запись и отмена в кабинете пишут событие в таблицу `OutboxEvent` в той же транзакции, что и Запись.
- Отправщик (`deliverPending`) шлёт события в Telegram-бот. Запускается после ответа (`after`, `src/app/outbox-kick.ts`): сразу после действия Клиента, попутно — после страниц кабинета и админки и после `/api/health/ready` (UptimeRobot — каждые 5 минут), не чаще раза в минуту на экземпляр. Запасной путь — `.github/workflows/outbox.yml` → `POST /api/cron/outbox` (cron GitHub здесь запаздывает на часы, на него не рассчитываем).
- Сбой — повтор с паузой 1, 2, 4 … 60 минут; после 8 попыток событие «Не доставлено» (DEAD) и видно в админке → «Уведомления», с кнопками «Отправить ещё раз» и «Пометить решённым».
- Сводка «За 7 дней» там же: событий, доля дошедших за 5 минут, недоставленные, самая долгая доставка. Это цифры решения 20 этапа 1.

## Настройки

Все три значения — только в секретах GitHub; `lab.yml` передаёт их в Vercel при каждой выкатке (`--env`), значения в переменных проекта Vercel они заменяют.

| Секрет | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather. Копия — в `.env.lab` |
| `TELEGRAM_CHAT_ID` | Чат Владельца — **не id бота** (число до двоеточия в токене). Отправщик сам ловит эту ошибку |
| `CRON_SECRET` | Ключ маршрута `/api/cron/outbox` для `outbox.yml`. Копия — в `.env.lab` |

После смены секрета нужна выкатка `main`: перезапустить последний запуск «Lab (Vercel)» по `push` (`gh run rerun <id>`) — у workflow нет ручного запуска.

## Что делать, если…

| Сигнал | Действия |
|---|---|
| Уведомление не пришло | Запустить «Outbox (Lab)» вручную (`gh workflow run outbox.yml`) и прочитать итог запуска: `HTTP 200: {"sent":…,"errors":[…]}`. `skipped: true` — нет токена или чата в Vercel; `HTTP 404` — не совпал `CRON_SECRET`; текст ошибки — ниже |
| `TELEGRAM_CHAT_ID — это id самого бота` | Узнать чат Владельца: Владелец пишет боту `/start`, затем `getUpdates` с токеном из `.env.lab` (скрипт не печатает токен; чат — поле `message.chat.id`). Новое число — `gh secret set TELEGRAM_CHAT_ID`, перевыкатка |
| `Telegram 401` | Токен отозван или неверен: новый токен в @BotFather → `.env.lab` → `gh secret set TELEGRAM_BOT_TOKEN` → перевыкатка |
| `Telegram 403: bot was blocked by the user` | Владелец остановил бота: открыть бота и нажать «Start», затем «Отправить ещё раз» в админке |
| `Telegram 403: the bot can't send messages to the bot` | В чате id бота — см. выше |
| `Telegram недоступен` / `Telegram 5xx` / `429` | Ничего: событие повторится само. Если за час не ушло — смотреть, зовёт ли UptimeRobot `/api/health/ready` (страница статуса) |
| Плашка «Не доставлено: N» в админке | Открыть «Уведомления», прочитать ошибку, устранить по таблице, «Отправить ещё раз». Если Владелец уже знает о Записи — «Пометить решённым» |
| Токен засветился (чат, лог, скриншот) | Сразу `/revoke` в @BotFather и смена токена, как при `401` |

## Чего не делать

- Не вписывать токен и чат руками в переменные проекта Vercel: источник один — секреты GitHub.
- Не присылать токен в чат и не печатать его в логах: проверять формат — длиной и первой частью, без значения.
- Не подключать уведомления к боевому сайту без решения Владельца и новой Политики (ADR 0016).
