# Runbook: релиз и hotfix боевого сайта

Боевой сайт https://athleticsgym.kz (hoster.kz) заморожен на релизном теге (ADR 0006). Merge в `main` уходит только в Лабораторию. Ветку `deploy`, которую забирает Plesk, обновляет только workflow **Deploy (hoster.kz)** — вручную, с выбором тега и подтверждением в GitHub Environments `production`.

| Что | Где |
|---|---|
| Текущий релиз | тег `v1.0.0` (= `a87788d`; код совпадает с `f2ad974`, отличие — только CLAUDE.md) |
| Сборка на хостинге | ветка `deploy`, коммит «Сборка из <тег> (<sha>)» |
| Workflow | `.github/workflows/deploy.yml`, запуск только из `main` |
| Подтверждение | GitHub → Settings → Environments → `production`, обязательный ревьюер |
| Настройка хостинга | `docs/hosting-plesk.md`; базы и миграции — `docs/deploy.md` |

**Никогда:** не нажимать **Re-run** у старых запусков Deploy (до 17 октября 2026 в них не было подтверждения — они перезапишут `deploy` без ревьюера); не пушить в `deploy` руками; не запускать workflow без решения Владельца.

## Релиз (новая версия клиенту)

1. **Решение Владельца.** Что именно выкатываем и когда — письменно (сообщение / письмо). Без него релиза нет. Время — когда в зале мало посетителей, и вы на связи час после выкатки.
2. **Выбрать коммит `main`** и проверить, что он годится для хостинга:
   - CI зелёный, включая прод-двойник (Docker с лимитами hoster.kz, MariaDB 10.4, ADR 0005);
   - миграции только добавляющие (старый код работает с новой схемой — иначе откат невозможен);
   - новые переменные среды заведены в Plesk **до** выкатки; ничего, что работает только на Vercel;
   - Политика конфиденциальности соответствует тому, что делает новый код (`CLAUDE.md`, «Юридические страницы»).
3. **Тег.** Версия: новая функция — `v1.Y.0`, только исправления — `v1.0.Z`.
   ```powershell
   git fetch origin --tags
   git tag -a v1.1.0 <sha> -m "v1.1.0: <что внутри>"
   git push origin v1.1.0
   ```
   Пуш тега ничего не выкатывает.
4. **Резервная копия.** Plesk → «Резервное копирование» → копия базы и файлов (или еженедельный дамп в `C:\gym-transfer\`, `docs/hosting-plesk.md`, раздел 6), если последней больше суток.
5. **Запуск.** GitHub → **Actions** → **Deploy (hoster.kz)** → **Run workflow** → *Use workflow from*: `main`, *tag*: `v1.1.0` → **Run workflow**.
6. **Подтверждение.** В запуске — «Waiting for review» → **Review deployments** → отметить `production` → **Approve and deploy**. Сборка ~5 минут; в `deploy` появится коммит «Сборка из v1.1.0 (…)».
7. **Plesk забирает ветку.** Если автоматическое получение не включено: Plesk → сайт → **Git** → **Получить** / **Развернуть**. Приложение перезапустится; `start.cjs` сначала применит новые миграции.
8. **Проверка (сразу, вручную):** `/ru`, `/kk`, вход в админку, `/api/health` с сессией Владельца, одна правка в админке видна на сайте. Сообщить Владельцу, что выкачено.

### Откат релиза

Запустить workflow заново с **предыдущим тегом** (шаги 5–7), например `v1.0.0`. Схему базы не откатываем: миграции только добавляющие, прежний код с новой схемой работает. Если сломаны данные — восстановление из резервной копии Plesk (`docs/hosting-plesk.md`).

## Hotfix (срочная правка прода от тега `v1.0.x`)

Когда: на проде ошибка, а в `main` уже есть то, что клиенту выкатывать нельзя.

1. **Ветка сопровождения** (один раз на линию `1.0`; если уже есть — пропустить):
   ```powershell
   git fetch origin --tags
   git switch -c release/1.0 v1.0.0
   git push -u origin release/1.0
   ```
   Пуш в `release/1.0` ничего не выкатывает и не запускает CI (в коде `v1.0.0` CI и Deploy слушают только push в `main`).
2. **Правка:** `git switch -c hotfix/<что> release/1.0` → минимальное исправление → PR **в `release/1.0`** (не в `main`). CI запускается на PR как обычно. Мерж после зелёного CI.
3. **Тег:** `git tag -a v1.0.1 origin/release/1.0 -m "v1.0.1: <что исправлено>"` → `git push origin v1.0.1`.
4. **Выкатка** — как в релизе, шаги 4–8, с тегом `v1.0.1`. Решение Владельца нужно и здесь (можно задним числом, если сайт лежал).
5. **Перенос в `main`:** `git switch -c port-v1.0.1 origin/main` → `git cherry-pick <sha исправления>` → PR в `main`. Иначе следующий релиз вернёт ошибку.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Запуск сразу «skipped» | Workflow запущен не из `main` — *Use workflow from*: `main` |
| «Ожидается релизный тег» | В поле tag не `vX.Y.Z` |
| Падает checkout | Тега нет в GitHub — `git push origin <тег>` |
| Нет кнопки подтверждения | Вы не в списке ревьюеров `production` (Settings → Environments) |
| Сайт после выкатки отдаёт 503/500 | Откат на предыдущий тег; логи — Plesk → Node.js → журнал (Посетитель называет «код ошибки» — это `digest`, ищите его в журнале); уроки запуска — `docs/hosting-plesk.md`. Если не забыт `MAINTENANCE_MODE=1` — убрать (`docs/hosting-plesk.md`, раздел 10) |
