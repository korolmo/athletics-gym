# Гостевая демо-админка Лаборатории со сбросом раз в сутки без планировщика

Статус: proposed (10 ноября 2026, grilling; `docs/stages/stage-p1-brand.md`, решения 6, 8–11, 15, 17–19).

Чтобы показать платформу работодателю или любому зрителю, нужен вход в админку без аккаунта Владельца. Правки зрителей не должны копиться, ломать данные замеров и попадать на боевой сайт.

## Решение

- **Гость демо-админки** входит кнопкой «Войти как гость» на `/admin/login`, без пароля. Вход включает переменная окружения, которая есть только в Лаборатории; в сборке для хостинга его нет (тест).
- **Роль в сессии Владельца**: «Владелец» или «Гость», сессия Гостя — 2 часа. `requireOwner` пускает обоих; действия, закрытые Гостю, начинаются с `requireRealOwner`. Закрыто: загрузка и удаление Фото, «Аккаунт», удаление сущностей, отмена Записей, повтор уведомлений. Телефоны Клиентов Гостю показываются скрытыми.
- **Общая база Лаборатории**: правки Гостей видят все; плашка в админке говорит об этом и о времени сброса.
- **Сброс раз в сутки — попутно.** При запросе к сайту или админке: с прошлого сброса прошли сутки и в поясе Клуба позже 04:00 — сброс после ответа (`after`), как отправка уведомлений (ADR 0017). Блокировка строкой в базе. Сбрасывается только то, что может менять Гость; Клиенты, Записи, очередь уведомлений и Обращения остаются.

## Considered Options

- **Песочница на каждого Гостя.** Копия данных на сессию — по сути изоляция П2; для демо слишком дорого.
- **Общий гостевой логин и пароль на странице.** То же, что кнопка, но неудобнее.
- **Cron GitHub или Vercel Cron.** Cron GitHub здесь опаздывает на часы (10 ноября `*/5` не сработал ни разу за 6 часов); Vercel Cron привязывает Лабораторию к Vercel.

## Consequences

- Если запросов нет, сброс ждёт первого запроса; UptimeRobot будит Лабораторию каждые 5 минут.
- Новое действие админки обязано решить, доступно ли оно Гостю: по умолчанию — `requireOwner`, опасное — `requireRealOwner`.
- В Политике Лаборатории — абзац о гостевом входе; на проде текст не меняется.
