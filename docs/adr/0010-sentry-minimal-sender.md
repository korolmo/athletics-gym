# Ошибки сервера — в Sentry своим отправщиком из onRequestError, без @sentry/nextjs

Ошибки сервера нужны в Sentry, но только из Лаборатории (ADR 0005, 0007): `SENTRY_DSN` задан только там. На хостинге и локально отправки нет. Только сервер: клиентский SDK не ставим (CSP без внешних скриптов, Политика конфиденциальности). Sentry wizard не запускали.

**Замер на прод-двойнике** (17 октября 2026, `npm run twin:measure`, 256 МБ / 1 CPU / MariaDB 10.4). `@sentry/nextjs` 10.76.2: `Sentry.init` в `instrumentation.ts`, `tracesSampleRate: 0`, `sendDefaultPii: false`, DSN-заглушка, без `withSentryConfig`. Черновой PR #41 закрыт без мержа.

| | без SDK | с SDK | разница |
|---|---|---|---|
| CI (Linux): RSS после запуска | 134,6 МБ | 154,6 МБ | **+20,0** |
| CI: RSS пик под нагрузкой | 200,7 МБ | 214,9 МБ | **+14,2** |
| CI: RSS после холодного старта | 151,3 МБ | 164,1 МБ | +12,8 |
| CI: p50 / p95 | 49 / 441 мс | 65 / 405 мс | в пределах разброса |
| Локально (Windows, Docker Desktop): после запуска / пик | 120,0 / 180,2 МБ | 138,5 / 200,8 МБ | +18,5 / +20,6 |

Заданный порог (> 25 МБ — свой отправщик) SDK не превысил. Свой отправщик выбран по другим причинам:

- **Запас памяти.** С SDK пик 215 МБ при пороге CI 230 и лимите хостинга 256 МБ: SDK забирает почти половину оставшегося запаса, а следующие этапы (outbox, журнал действий) тоже будут расти в памяти.
- **Персональные данные.** Свой код шлёт только белый список полей: тип и текст ошибки, стек, маршрут без query, метод, digest Next, release, среда. Заголовков, cookies, тел, полей форм и IP нет, это закреплено тестом. У SDK это настройки и интеграции, за которыми надо следить при каждом обновлении.
- **Нужно мало.** Хватает ошибки со стеком и маршрутом, которую ловит `onRequestError` (Next 15). Трассировки, breadcrumbs и replay в рамках этапа 0 не нужны.

`src/lib/observability/sentry.ts` — около 130 строк без зависимостей: разбор DSN, событие, конверт (envelope) в `POST /api/<project>/envelope/` с `X-Sentry-Auth`, тайм-аут 2 с; отправщик никогда не бросает исключений. Подключается лениво в `onRequestError`, только при заданном `SENTRY_DSN`, поэтому без DSN к памяти не прибавляет ничего. Проверено: Sentry принимает конверт; `POST /api/health/error` (Владелец) на Лаборатории бросает ошибку, и она уходит в Sentry.

## Considered Options

- **`@sentry/nextjs` без wizard** — +14…20 МБ, больше возможностей (трассировка, контекст, source maps), но больше поверхности для персональных данных и меньше запас памяти.
- **Только логи (ADR 0009)** — ошибки и так видны в JSON-логах, но без группировки, уведомлений и истории.

## Consequences

- Нет source maps: стеки указывают на собранные файлы `.next/server`. Если это станет мешать, загрузка source maps — отдельное решение.
- Ошибки вне запросов (фоновые задачи этапа 1) не ловятся автоматически: их отправляют явным вызовом `captureError`.
- Включать Sentry на проде — отдельное решение (ADR 0005): данные уходят из РК, нужна запись в Политике конфиденциальности.
- Если понадобятся трассировка или профили, `@sentry/nextjs` можно вернуть: замер выше — отправная точка.
