# Фотографии хранятся в Supabase Storage

Владелец загружает фото (зал, Тренеры, галерея) с телефона через админку; файлы кладём в Supabase Storage, а в базе храним только путь к файлу. Supabase уже используется как база, бесплатного 1 ГБ хватает на фото одного зала, а сжатие и размеры под устройство даёт `next/image`.

## Considered Options

- Vercel Blob — проще с Vercel, но ещё один платный лимит и привязка к хостингу.
- Cloudinary — сам обрезает и сжимает, но это отдельный сервис и аккаунт.

## Consequences

Уточнено на этапе 2 (9 октября 2026), когда загрузка была сделана.

- **Файл идёт из браузера прямо в хранилище**, мимо нашего сервера: сервер только выдаёт подписанную ссылку на одну загрузку. Иначе фото упиралось бы в лимит тела запроса у функций Vercel (4,5 МБ) и шло бы через сеть дважды. Цена — загрузка в два шага (файл, потом запись в базу) и уборка файлов, брошенных между шагами.
- **Бакет `media` публичный**: фото сайта и так видны всем, а прямые ссылки позволяют `next/image` брать файлы без подписи. Писать в бакет можно только по подписанной ссылке или ключом `service_role`; ограничения на тип и размер файла заданы в самом бакете, а не только в коде.
- **Ключ `service_role` — только на сервере** (переменные без `NEXT_PUBLIC`). В браузер не попадает ни он, ни анонимный ключ: клиентская библиотека Supabase в браузере не используется.
- **У каждой базы своё хранилище** того же проекта Supabase: пути в базе разработки указывают на файлы проекта разработки, в боевой — боевого. Скопировать базу без файлов — получить битые ссылки.
- **Сжатие — в браузере Владельца** (до ~1600 px, WebP), потому что Supabase Storage на бесплатном тарифе изображения не преобразует; размеры под устройство даёт `next/image`.
- **Картинки из `public/` остаются запасным вариантом**: пока Фото не загружено или хранилище недоступно при сборке, сайт показывает их.
