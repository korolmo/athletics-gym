# Модель мощности: k6 рядом с прод-двойником, цель 10× пика, кэш по замеру

Статус: proposed (13 ноября 2026, grilling; `docs/stages/stage-7-load-cache.md`, решения 1–4, 6–9).

Прод-двойник (ADR 0005) проверяет память и p95 на одной фиксированной нагрузке: 8 кругов по 4 параллельных запроса. Он не отвечает на вопрос, сколько Посетителей выдержит hoster.kz (256 МБ, 1 CPU, один процесс) и что сломается первым. Кабинет и админка читают базу на каждом запросе, кэша данных между запросами нет.

## Решение

- **Колено — главная метрика мощности:** запросы в секунду смеси маршрутов, при которых ещё p95 ≤ 1 с, нет 5xx и RSS ≤ 230 МБ. Ищем ступенями до отказа.
- **k6 в отдельном контейнере рядом с двойником.** Генератор нагрузки не делит память и CPU с измеряемым процессом. Доли маршрутов берутся из строк доступа Лаборатории, сценарий Клиента (вход → Окна → Запись) добавлен вручную.
- **Цель — 10× оценки пика:** 20 запросов в секунду при оценке 2. На каждом PR — проверка на этой скорости 60 секунд; поиск колена — еженедельно и вручную.
- **Кэш данных Next с тегами — только по замеру,** для узких мест кабинета. Сброс делает `revalidateSite()`, а админка всегда читает базу.
- **Только двойник.** Лабораторию и боевой сайт не нагружаем.

## Considered Options

- **Расширить скрипт двойника вместо k6.** Нагрузка в том же Node, что и замер памяти, искажает его; ступени и пороги пришлось бы писать самим.
- **`"use cache"` Next 16.** Требует `cacheComponents`, а это новая модель отрисовки, под которой надо перепроверять ISR-главную и страницы ошибок (ADR 0013).
- **Кэш в памяти процесса с TTL.** Тратит память, которой 256 МБ, а на Vercel экземпляры расходятся по свежести.
- **Нагружать Лабораторию.** Стоит денег Vercel и TiDB, портит SLO и замеры других этапов и мерит не тот хостинг.

## Consequences

- CI на каждом PR длиннее примерно на 1,5 минуты: прогон k6 на целевой скорости.
- Оценка пика — допущение. Когда появится статистика прода (если Владелец её разрешит), цель пересматривается.
- Если за коленом первым приходит OOM, нужен лимит запросов в работе в `start.cjs` — отдельное решение.
