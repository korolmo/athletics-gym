# Сайт, база и фото — на виртуальном хостинге hoster.kz (Plesk, MariaDB)

Сайт должен работать на домене .kz с серверов в Казахстане, а данные Посетителей (Отзывы, Согласие) — храниться в РК. Vercel и Supabase (Франкфурт) этому не отвечают, поэтому весь проект переезжает на виртуальный хостинг hoster.kz, тариф «Эконом-1» с Plesk: Node.js 23 (Passenger), MariaDB 10.4 на localhost, 1 ГБ диска, 256 МБ памяти, домен athleticsgym.kz. Сайт, админка и все данные остаются в одном Next.js-проекте (ADR 0001) — меняются только база, хранилище фото и способ выкатки.

## Что меняется

- **База: PostgreSQL → MariaDB 10.4** (другой на хостинге нет). Prisma с `provider = "mysql"`; история PostgreSQL-миграций уходит в архивную папку, для MariaDB — новая базовая миграция (уточняет ADR 0003). Локально и в CI — MariaDB 10.4 в Docker.
- **Фото — на диске хостинга**, в папке `MEDIA_DIR` вне папки, которую перезаписывает выкатка; раздаёт и принимает их наш сервер (`/media/...`), с проверкой сессии Владельца, типа файла по содержимому и общего лимита объёма. Заменяет ADR 0002 после переключения.
- **Облегчённый Next под 256 МБ**: `output: "standalone"`, без оптимизации картинок на сервере (`images.unoptimized`, без `sharp`): размеры WebP для `public/` готовит CI, для загруженных Фото — браузер Владельца. Куча Node ограничена `NODE_OPTIONS`, кэш Next в памяти — минимальный.
- **Выкатка без SSH**: GitHub Actions собирает готовый сервер и кладёт его в ветку `deploy` (только собранные файлы, без исходников и секретов); Plesk «Развернуть с помощью Git» забирает её и перезапускает приложение. Миграции — npm-скрипт из сборки, запускаемый в Plesk до нового кода.
- **Секреты — только в переменных среды Plesk.** Признак боевой среды — `APP_ENV=production` (запасной — `VERCEL_ENV`), всё остальное — `noindex`.
- **Превью Vercel на каждую ветку больше нет** (без базы они бы падали); проверка ветки — локально и в CI.

## Considered Options

- **Остаться на Vercel + Supabase** — проще и быстрее, но данные и сайт вне РК: не подходит по закону.
- **VPS в Казахстане** (PostgreSQL, Docker, своя память) — оставил бы стек как есть, но дороже и требует администрирования сервера (обновления, бэкапы, защита), которого у зала нет.
- **Тариф с PostgreSQL** — у hoster.kz на виртуальном хостинге его нет.

## Consequences

- **Память — главный риск.** Next 15 standalone обычно занимает 100–180 МБ; если Passenger запустит два процесса или хостинг считает память иначе, чем `process.memoryUsage`, упрёмся в 256 МБ. Реальный лимит и способ его учёта узнаём диагностикой (шаг 0), запас подтверждаем замером под нагрузкой. Не хватит — тариф выше, а не урезание сайта.
- **Холодный старт**: Passenger останавливает приложение, когда к нему долго не обращаются, — первый запрос после простоя медленнее. Кэш страниц на диске (`.next`) переживает перезапуск, кэш в памяти — нет.
- **Диск 1 ГБ** делят сборка, фото, логи и, возможно, резервные копии Plesk. Отсюда лимит общего объёма Фото с понятной ошибкой в админке.
- **MariaDB 10.4 больше не получает обновлений** (поддержка закончилась в июне 2024). База доступна только с localhost, так что риск ограничен; при переходе хостинга на новую версию — проверить миграции и тесты на ней.
- **Без SSH и внешнего доступа к базе** перенос данных — через SQL-дамп и импорт в Plesk, файлы — через zip и Менеджер файлов; миграции — только через команды Plesk.
- **Политика конфиденциальности**: место хранения данных — поле Настроек сайта. При переключении Владелец меняет его на «на серверах в Республике Казахстан (hoster.kz)»; начальное значение в коде и упоминания Vercel/Supabase/cookie/сторонних сервисов в текстах — сверить в той же ветке (правило из CLAUDE.md про Политику).
- **Адрес сайта** меняется на `https://athleticsgym.kz` (`SITE_URL`); `athletics-gym.vercel.app` после переключения перенаправляет на него, в Search Console — «Изменение адреса».

## Как сделано (15 октября 2026, ветка stage-8-plesk)

Диагностику сервера (шаг 0) пропустили: SSH нет, точная ОС и лимиты неизвестны, поэтому всё сделано с запасом.

- **Prisma — движок на Rust**, в сборке четыре варианта Linux (`binaryTargets`: debian и rhel, OpenSSL 1.1 и 3.0); Prisma сама выбирает подходящий. Драйвер-адаптер MariaDB без Rust-движка в Prisma 6 — preview-возможность, оставлен запасным вариантом на случай нехватки памяти.
- **Миграции без Prisma CLI**: `scripts/standalone/migrate.cjs` применяет `prisma/migrations` и ведёт ту же таблицу `_prisma_migrations`. CLI с движками схемы под все Linux занял бы ещё ~100 МБ диска, а запустить его без SSH негде. Файл запуска Plesk — `start.cjs`: сначала миграции (с блокировкой `GET_LOCK`), потом сервер Next, — так порядок «сначала миграция, потом код» соблюдается сам.
- **Ветка `deploy` — один коммит без истории**, перезаписывается при каждой сборке: копия репозитория в Plesk не растёт на диске 1 ГБ. Выкатка Plesk не удаляет файлы, исчезнувшие из ветки, поэтому `start.cjs` убирает старые файлы `.next/static` и `public/_img` по списку `build-files.txt`.
- **Лимит Фото — 500 МБ** (`MEDIA_QUOTA_MB`): на том же диске — приложение (~115 МБ), копия репозитория Git, кэш страниц и логи.
- **Копии картинок**: для `public/` — WebP 64–1200 px при сборке (`scripts/images/build-variants.mjs`), для Фото — 400 и 800 px по ширине в браузере Владельца; `src/lib/image-loader.ts` подставляет их в srcset. Логотипы — обычные файлы `public/`, а не импорт модулей.
- **Замер памяти** (`npm run memory:check`, 20 кругов: все страницы и документы, картинки, превью ссылок, админка, счётчик, 60 загрузок Фото — 3220 запросов без ошибок): Linux-контейнер `node:23-bookworm-slim`, лимит 256 МБ без подкачки, 1 CPU, `--max-old-space-size=160` — RSS после запуска 115 МБ, под нагрузкой медиана 190 МБ, максимум 194 МБ, через 10 с простоя 182 МБ; куча V8 — до 68 МБ. Запас — около 60 МБ, если хостинг считает память по RSS одного процесса.
- **Перенос данных** проверен на копии боевой базы: дамп импортируется в MariaDB 10.4, все строки совпадают с Supabase значение в значение, видимый текст `/ru` и `/kk` совпадает с боевым сайтом.

## План отката

До переключения боевой сайт на Vercel и боевая база Supabase не трогаются. После переключения их не удаляем минимум 30 дней: Vercel-проект остаётся (main можно выкатить командой `vercel deploy --prod`), Supabase — без изменений.

Если на hoster.kz что-то не так: снять редирект с `athletics-gym.vercel.app`, вернуть `SITE_URL`, в DNS athleticsgym.kz направить на Vercel (или временно вести с него на vercel.app). Данные, появившиеся на новом хостинге после переключения (Отзывы, Обращения, Фото, правки Настроек), без обратного переноса потеряются — поэтому откат проще всего в первые дни, и порядок обратного переноса описан в `docs/hosting-plesk.md`.
